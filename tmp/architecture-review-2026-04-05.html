Collapse the command dispatcher

Strong in-process

Files

commands/commands.py (1,122 lines) · commands/__init__.py (3 lines) · 22 handler files in commands/

Before — 40 branches, no registry

After — command registry, one seam

Problem

40 ad-hoc if cmd == branches, each with duplicated try/except; 9 parameters; adding a command touches 3 places.

Solution

A CommandRegistry dict mapping command name to handler, registered in commands/__init__.py.

Wins

  • Locality: bugs concentrate in registry
  • Leverage: 1 error boundary, N handlers
  • Interface shrinks: 9 params → 2
  • Seam visible: register() is one call
  • Delete 1,100 lines of dispatcher

Split SessionState into focused state holders

Before — one dataclass, 25+ fields

After — focused state holders

Problem

SessionState holds 25+ fields spanning 5 domains (UI, agent, remote, background tasks, tracking). Every feature adds a field, creating implicit cross-domain coupling.

Solution

Split into focused state holders: UISettings, AgentRuntime, RemoteBridgeState, BackgroundTaskState, TrackingState.

Define a CommandHandler protocol

Worth exploring in-process

Files

22 handler files in commands/ · commands/__init__.py 

            # Before: 22 handlers, 22 different signatures
            def handle_model_command(settings, session_state, args): ...
            def handle_skills_command(args, session_state, settings): ...
            def handle_ralph_command(cmd, cmd_args, session_state, settings): ...

            # After: 1 protocol
            class CommandHandler(Protocol):
                def __call__(self, args: Namespace, state: SessionState) -> None: ...

            # Handler registers itself:
            register("model", ModelHandler())
            register("skills", SkillsHandler())

Problem

22 handler files with no shared abstraction. Adding --json output support requires touching all 22. Parameter ordering varies between handlers; the current commands.py dispatcher passes them manually.

Solution

Define a CommandHandler protocol and wrap each handler as an adapter. The registry dispatches generically instead of passing parameters per-handler.

Wins

  • Leverage: add --json once, all handlers
  • Seam: handlers are just adapters at the seam
  • Testable: handler(args, state) → test input/output

  • Clearer: session package owns session semantics

Top recommendation

Tackle candidate #1 first — Collapse the command dispatcher.

It's the highest-leverage, lowest-risk change. A CommandRegistry replaces 1,122 lines of commands.py with a dict-based registration pattern. The refactor is mechanical (each if cmd == "x" branch becomes registry.register("x", fn)), so it can be done incrementally without breaking anything. It also lays the groundwork for candidates #3 (App orchestrator) and #6 (CommandHandler protocol) — once commands are registered centrally, wrapping them in a protocol or wiring them into an App class is straightforward.
