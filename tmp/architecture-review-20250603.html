Coupling Latent Bug

Plan Mode Tool Lists are Duplicated with Drift

STRONG
ui/hitl_approval.py agents/plan_agent/plan_mode_middleware.py agents/plan_agent/plan_agent.py prompts/plan_agent.jinja

The blocked tool set for plan mode is defined independently in two modules with different contents: one blocks write_todos but not git_stash; the other does the opposite. A third listing exists in the prompt template. Plan mode behaviour depends on which enforcement code path fires first — a dual-source-of-truth that invites silent divergence.

🔴 Problem

  • Two independently-maintained block lists will diverge
  • Neither matches the other's tool set exactly
  • No single file tells you "what is blocked in plan mode?"

✅ Solution

  • Define blocked tools once in a shared config/plan_mode.py
  • Both enforcement modules import from the single source
  • Prompt template is rendered from the same set
📈 Leverage gain: High — eliminates a latent correctness bug
📍 Locality gain: "What's blocked in plan mode?" answerable from one file
🧪 Test improvement: Value-level tests on the shared constant set
🗑️ Deletion test: Can't delete either list without changing behaviour — they should be one list

prompts/__init__.py — Over-Engineered Cache

SPECULATIVE
prompts/__init__.py (72 lines)

This file wraps Jinja2 with a TTL-based manual cache dictionary (~50 lines of infrastructure for 2 lines of actual template.render(**kwargs) logic). A @lru_cache decorator or simply eliminating the cache would reduce the module to ~15 lines without losing functionality.

Shallowness ratio: 50 lines cache / 2 lines rendering Very Shallow

🔴 Problem

  • Manual TTL cache duplicates Jinja2's built-in caching (disabled via auto_reload=False)
  • Cache logic (50 lines) dwarfs rendering logic (2 lines)
  • @lru_cache would provide the same benefit with 1 line

✅ Solution

  • Replace manual cache with @functools.lru_cache
  • Or inline: env.get_template(name).render(**kwargs)
  • Cut module from 72 lines to ~15
🗑️ Deletion test: Delete the cache layer → 15-line module, same behaviour
